## 0. 先分清“配置结果”和“播放画面”

**技能逻辑资产**回答：什么时候触发、满足什么条件、影响谁、造成多少伤害或治疗、添加什么状态。

**技能表现资产**回答：第几帧播放动作、第几帧移动、在哪里出特效、什么时候显示受击与死亡画面。

**技能定义资产**把逻辑、表现、技能编号、消耗和选目标方式组合起来。只有创建逻辑和表现文件，技能还没有进入战斗。

**战斗定义资产**配置参加战斗的单位、属性、携带技能和可用的技能定义。

**18 位阵容预览资产**配置编辑器演示用的模型和站位。换预览武将，不会给实战单位换技能、攻击力或模型。

| 想改什么 | 去哪里改 | 一个例子 |
| --- | --- | --- |
| 伤害从 135% 改为 150% | 技能逻辑 → 参数与变量 | damage_rate：135 → 150 |
| 伤害数字出现得晚一点 | 技能表现 → 伤害与飘字 | 开始帧：12 → 15 |
| 单体攻击改成全体攻击 | 技能定义的目标模式，并核对逻辑操作目标 | 全体敌人＋技能选中目标 |
| 预览时用关羽，不用赵云 | 预览角色 → 预览施法者 | 选择 2 号位关羽 |
| 实战关羽携带这个技能 | 战斗定义 → Units → Skill Ids | 添加该技能编号 |
| 模型本身没有指定动作 | 模型动画资源 | 核对真实动作名，不能靠改备注解决 |

请先记住四条规则：

1. **表现编辑器中的“播放”不进行真正的战斗数值计算。**
2. **在表现时间轴上多放一个“伤害与飘字”，不会增加一次逻辑伤害。**
3. **把“死亡表现”放到某一帧，不会把活着的单位杀死。**
4. **“检查配置”通过，说明当前结构和引用检查通过；资源能否加载、被动是否正确触发，还要进入战斗验证。**

## 2. 开工前：把一句技能描述拆成配置单

先填写这张表，再打开编辑器。需求未写清楚时，容易把“释放时”“命中时”“造成伤害后”配成同一种触发。

| 项目 | 必须写清楚的问题 | 本手册第一个技能 |
| --- | --- | --- |
| 技能类型 | 主动技能，还是监听事件的被动技能？ | 主动 |
| 触发时机 | 技能释放、行动开始、伤害完成、单位死亡？ | 本技能释放 |
| 目标 | 单个敌人、全部敌人、自身、生命最低友军？ | 单个敌人 |
| 数值 | 固定伤害，还是按谁的哪个属性计算？ | 自身攻击力的 135% |
| 伤害规则 | 能否闪避、暴击、是否无视防御？ | 首次测试全部关闭 |
| 状态 | 状态编号、触发概率、作用对象、持续规则？ | 第一阶段不加状态 |
| 画面 | 哪个动作、哪一帧命中、是否位移、何时返回？ | 突进 → 攻击 → 受击 → 返回 |
| 验收 | 什么数据能证明配置正确？ | 攻击 100、防御 10时，伤害 125 |
| 特殊情况 | 空目标、死亡目标、满血、未命中时怎么办？ | 排除死亡目标；后续单独测闪避与暴击 |

### 2.1 为本例准备名称和编号

以下编号仅为教学示例。复制使用前确认它们没有被当前战斗的其他技能占用。

| 项目 | 本例 | 唯一性与用途 |
| --- | --- | --- |
| 技能编号 | 101012 | 作为技能身份；在同一战斗数据库中必须唯一，项目内统一分配 |
| 主伤害规则编号 | 10101201 | 所有编入同一战斗的规则之间必须唯一 |
| 可选概率状态规则编号 | 10101202 | 每条规则使用不同编号 |
| 逻辑标识 | skill_logic_101012 | 逻辑资产内部稳定标识 |
| 表现标识 | skill_101012 | 时间轴内部稳定标识，不与其他表现冲突 |
| 逻辑文件 | skill_logic_101012.asset | 放在 Skills/Logic |
| 表现文件 | skill_101012.asset | 放在 Skills/Expression |
| 技能定义文件 | skill_101012.asset | 放在 Skills/Definitions |

完整目录前缀：

~~~text
Assets/GameResources/Battle/TurnBased/Skills/
~~~

文件名和资产内部的“逻辑标识 / 表现标识”不是同一字段。改文件名后，要检查内部标识是否也符合预期。

资产列表现在显示中文说明与标识，并支持中文搜索。建议“说明”的第一行写短名称，例如“关羽·突进斩击”，后面再写完整描述。

### 2.2 准备资源

- 确认要预览的模型实际存在，并能播放待机。
- 确认攻击动作的真实名字，例如 attack_1；示例名字不是所有模型都必须具备的标准。
- 特效、音效准备好项目认可的资源标识。资源名称、文件路径和资源加载地址不一定相同。
- 第一次可先不放特效、音效，完成“动作＋位移＋伤害表现”后再补。

## 3. 技能逻辑编辑：按三页依次填写

入口：**工具 → 战斗 → 技能逻辑编辑器**。

当前三个页签：

| 页签 | 负责什么 | 首次配置时怎么用 |
| --- | --- | --- |
| 规则配置 | 触发事件、条件、操作和目标 | 决定技能如何执行 |
| 参数与变量 | 策划参数、临时数值、技能状态 | 先定义，后在规则中引用 |
| 提供给表现的数据 | 输出标识、对应事件、说明 | 声明表现可引用的数据名称 |

### 3.2 新建时已经有什么

新建逻辑资产默认带有主动伤害示例，通常已经包含：

- 一个伤害结算轨道。
- 一条“技能释放”规则。
- damage_rate 参数。
- temp_value 单次触发变量。
- cast_count 技能实例变量。
- 依次“计算伤害 → 造成伤害 → 累计释放次数”的三个操作。
- damage_result 输出声明。

**先检查并修改默认内容，不要在已有伤害操作后又新增一份相同伤害。**

顶部“数据模板”只补充数据定义，不会替你写出完整的新规则。已有同名定义不会被覆盖；推荐编号被占用时，模板会选择后续可用编号。引用时以实际生成的数据编号为准，优先使用下拉框。

### 3.3 参数、临时变量、技能变量怎么选

~~~mermaid
flowchart TD
    A["这个数值用来做什么？"] --> B{"策划提前填好，战斗中只读取？"}
    B -- 是 --> C["策划参数<br/>倍率、概率、状态编号"]
    B -- 否 --> D{"只在当前这一条规则里读写？"}
    D -- 是 --> E["单次触发变量<br/>暂存本次伤害等中间值"]
    D -- 否 --> F["技能实例变量<br/>本场释放次数、上次触发回合"]
    E --> G["先写入，再在同一条规则后续操作读取"]
    F --> H["每个单位的每个技能实例各自保存"]
~~~

| 类型 | 是否可由逻辑操作改写 | 生命周期 | 常见误区 |
| --- | --- | --- | --- |
| 策划参数 | 否 | 来自技能配置 | 把它当测试专用数值；实际上会影响实战 |
| 单次触发变量 | 是 | 每条规则触发开始时重新初始化；未写入时读取定义默认值 | 想在下一条规则里继续读取上条规则的结果 |
| 技能实例变量 | 是 | 当前战斗中该单位的该技能实例 | 以为所有武将会共享同一份 cast_count |
| 战斗计数器 | 是，通过计数器相关操作 | 当前战斗全局共享 | 与技能实例变量混用，导致不同单位互相影响 |

编号可以相同但含义不同。例如“技能参数编号 1001”“技能编号 1001”“状态编号 1001”属于不同配置空间。填写时看字段用途，不能只看数字。

### 3.4 本例的数据定义

进入“参数与变量”，把以下三项核对完整：

| 程序标识 | 数据编号 | 数据种类 | 值类型 | 变量作用域 | 默认值 | 策划说明 |
| --- | ---: | --- | --- | --- | ---: | --- |
| damage_rate | 1001 | 策划参数（只读） | 百分比（%） | 参数不需要选择 | 135 | 本技能基础伤害倍率 135% |
| cast_count | 2001 | 运行时变量 | 整数 | 技能实例整场 | 0 | 该单位本技能释放次数 |
| temp_value | 3001 | 运行时变量 | 整数 | 单次规则触发 | 0 | 本次规则计算的基础伤害 |

程序标识建议稳定英文，例如 damage_rate；策划说明写中文。需要导出程序常量时，避免空格、中文标识和随意改名。

### 3.5 所有百分比都填写实际百分数

**统一规则：135% 填 135，30% 填 30，12.5% 填 12.5。无需手动放大数值。**

| 所在位置与字段 | 100% | 135% | 30% |
| --- | ---: | ---: | ---: |
| 逻辑编辑器、普通 Inspector 的“倍率（%）” | 100 | 135 | 30 |
| 数据定义“默认值”，值类型为“百分比（%）” | 100 | 135 | 30 |
| 动态倍率读取的百分比参数或变量 | 100 | 135 | 30 |
| 动态倍率的“固定倍率（%）” | 100 | 135 | 30 |
| 生命百分比条件的“比较值（%）” | 100 | 不适用于正常生命比例 | 30 |

百分比支持两位小数，例如 12.55%。概率通常填写 0～100；伤害倍率和暴击伤害可以超过 100。整数、计数和配置编号仍填写整数。

生命比例、随机百分比、暴击率等百分比来源会自动识别单位：例如“生命比例 < 固定值 50”表示低于 50%，“随机百分比 < 固定值 30”表示 30% 概率。对百分比变量执行“设置/累加”时，固定值和偏移也使用实际百分数，例如累加 5 表示增加 5 个百分点。

动态倍率应引用“百分比（%）”类型的参数或变量。独立的固定百分比表达式可以开启“固定值使用百分比”；通常按比较对象或目标变量自动识别即可。

更新工具后，旧战斗配置会按版本标记自动迁移一次，保留原来的数值效果，无需手动执行迁移命令。编译后的定点数内部表示由工具处理，策划只编辑实际百分数。

**例：动态倍率已经读取 damage_rate = 135 时，不要再额外乘一遍 135%。**

### 3.6 本例的主伤害规则

进入“规则配置”，选择默认伤害轨道和默认规则。

| 字段 | 填写值 | 说明 |
| --- | --- | --- |
| 轨道名称 | 伤害结算 | 用于整理逻辑 |
| 规则名称 | 本技能释放时结算伤害 | 名称应描述实际触发时机 |
| 触发事件 | 技能释放 | 当前技能释放时执行 |
| 拥有者必须存活 | 开启 | 新手主动技能保持开启 |
| 高级设置 → 规则编号 | 10101201 | 不要沿用复制出来的旧编号 |
| 高级设置 → 执行阶段 | 主阶段 | 本例无需调整 |
| 高级设置 → 优先级 | 0 | 同阶段数字越小越先执行 |
| 触发条件 | 空 | 不要求额外条件 |

运行时会为“技能释放”事件核对释放者和技能编号，默认主动规则不需要另外加一条“是自己释放的技能”条件。

“主阶段 / 前置阶段 / 后置阶段”目前用于规则排序；不要把阶段当作动画帧，也不要认为改成前置阶段就能修改尚未结算的原始伤害。

### 3.7 操作一：计算伤害，写入 temp_value

选择第一个逻辑操作：

| 字段 | 填写值 |
| --- | --- |
| 操作名称 | 计算本次基础伤害 |
| 操作类型 | 设置单次触发变量 |
| 选择参数或变量 / 数据编号 | temp_value / 3001 |
| 数值来源 | 拥有者属性 |
| 属性 | 攻击 |
| 使用动态倍率 | 开启 |
| 动态倍率 → 倍率来源 | 策划参数 |
| 动态倍率 → 选择参数或变量 | damage_rate / 1001 |
| 最终偏移 | 0 |
| 启用下限、启用上限 | 暂时关闭 |

计算：

~~~text
拥有者攻击 = 100
damage_rate = 135
temp_value = 100 × 135 ÷ 100 = 135
~~~

这里得到的是送入伤害结算的基础数值，还没有扣防御、算暴击或吸收护盾。

### 3.8 操作二：读取 temp_value，造成伤害

选择第二个逻辑操作：

| 字段 | 填写值 |
| --- | --- |
| 操作名称 | 对技能选中目标造成伤害 |
| 操作类型 | 造成伤害 |
| 操作目标 → 目标类型 | 技能选中目标 |
| 数量上限 | 0，表示不额外限制 |
| 包含死亡单位 | 关闭 |
| 配置编号过滤 | 0，不过滤 |
| 数值来源 | 单次触发临时变量 |
| 选择参数或变量 | temp_value / 3001 |
| 使用动态倍率 | 关闭 |
| 倍率（%） | 100 |
| 最终偏移 | 0 |
| 启用下限 / 最小值 | 开启 / 1 |
| 启用上限 | 关闭 |
| 伤害选项 | 首次测试不勾选闪避、暴击、无视防御 |

数量上限 0 不会把“单个敌人”自动改为全体敌人：这里处理的是技能已经选中的目标集合。技能定义的目标模式决定释放时选出哪些目标。

### 3.9 操作三：记录释放次数

| 字段 | 填写值 |
| --- | --- |
| 操作名称 | 本场释放次数加一 |
| 操作类型 | 累加技能实例变量 |
| 选择参数或变量 | cast_count / 2001 |
| 数值来源 | 固定值 |
| 固定值 | 1 |
| 使用动态倍率 | 关闭 |
| 倍率（%） | 100 |
| 最终偏移 | 0 |

三个操作按以下顺序排列：

~~~text
1. temp_value = 自身攻击 × damage_rate
2. 用 temp_value 对选中目标造成伤害
3. cast_count 加 1
~~~

“伤害在列表前面，计算变量在后面”会读到错误的中间值。

变量写入与读取适合在同条规则中顺序安排。真正的伤害、治疗、状态等进入战斗操作队列，不要假设“列表上一项造成伤害”后下一项数值表达式一定已经读到了扣血后的生命；需要观察已结算结果时，使用相应完成事件。

### 3.10 声明提供给表现的数据

进入“提供给表现的数据”，确认：

| 输出标识 | 事件类型 | 说明 |
| --- | --- | --- |
| damage_result | 伤害结算完成 | 本技能伤害结果的声明名称 |

输出标识应稳定、非空且在当前逻辑资产中唯一。它不是变量编号，也不是特效资源地址。

**当前能力边界：**输出声明和“读取逻辑结果”会进行名称与引用一致性检查；目前内置表现播放主要接收主目标的一条伤害结果。输出标识没有实现任意事件的自动分发与播放条件控制。例如给“状态飘字”绑定 buff_added，并不能保证它只在状态添加成功时播放。概率状态提示、动态治疗数字和复杂事件路由需要项目扩展，不能仅靠填写输出名称完成。

### 3.11 保存与检查

点击 **“检查配置”**。通过后工具会保存；也可以单独点“保存”。

失败时先读窗口里的具体错误：

- 编号不存在：到“参数与变量”检查定义，再从下拉框重新选择。
- 参数 / 变量种类或作用域不匹配：例如“设置技能实例变量”不能引用单次触发变量。
- 规则编号重复：修改“规则高级设置”里的编号；资产间是否重复还要检查整体战斗编译。
- 规则没有操作：至少保留一个有效操作。
- 布尔默认值错误：只能填写 0 或 1。
- 最小值大于最大值：调整上下限。
- 输出标识为空或重复：整理输出列表。

“导出程序常量”用于生成程序可引用的编号和名称；**不是保存、播放或日常调整数值的前置步骤**。

## 4. 逻辑字段速查：遇到新需求时查这里

### 4.1 事件和条件的判断流程

~~~mermaid
flowchart TD
    A["收到战斗事件"] --> B{"触发事件类型匹配？"}
    B -- 否 --> X["本次不执行这条规则"]
    B -- 是 --> C{"拥有者存活要求满足？"}
    C -- 否 --> X
    C -- 是 --> D{"技能释放事件是否来自该单位的该技能？"}
    D -- 否 --> X
    D -- 是或其他事件 --> E["建立本条规则的临时变量上下文"]
    E --> F["按顺序检查全部条件"]
    F --> G{"每条条件都通过？"}
    G -- 否 --> X
    G -- 是 --> H["按列表顺序处理操作"]
    H --> I["执行战斗操作，产生后续事件"]
~~~

| 常用触发事件 | 典型用途 | 特别注意 |
| --- | --- | --- |
| 战斗开始 | 开场状态、初始计数 | 事件没有普通单位目标，需要明确选择规则拥有者等目标 |
| 回合开始 / 回合结束相关时机 | 回合类机制 | 当前列表有“回合开始”，不要把“行动结束”当“回合结束” |
| 行动开始 / 行动结束 | 每次轮到某个单位时触发 | 想限制为自己，添加“事件目标是自身”条件 |
| 技能释放 | 主动技能伤害与治疗 | 自动核对当前技能和释放者 |
| 伤害结算完成 | 受伤被动、伤害完成后的反应 | 需要检查事件攻击者或事件目标与自身的关系 |
| 生命变化 | 血量阈值机制 | 治疗或伤害都可能导致；谨防反复触发链 |
| 治疗完成 | 治疗后的被动 | 区分施加治疗者和被治疗者 |
| 获得增益或减益 / 移除增益或减益 | 状态联动 | 确认当前状态与单位关系，复杂状态过滤需核对现有条件能力 |
| 单位死亡 / 单位复活 | 击杀、死亡、复活机制 | 自身死亡后要执行的规则不能要求拥有者仍存活 |
| 战斗结束 | 结算机制 | 区分结算逻辑和画面效果 |

下拉框中的“伤害结算前”“单位召唤”不代表已经具备完整可配机制。当前伤害服务没有完整的可修改前置伤害管线；召唤需要程序创建单位并接入召唤服务，逻辑编辑器尚无完整的召唤配置操作。此类需求先与程序确认。

### 4.2 条件、目标和“全部满足”

**一条规则有多条条件时，全部满足才执行。**

**某条条件选中了多个单位时，通常要求选出的每个单位都满足该条件；它不是“任意一个满足”。**“目标数量比较”“两个动态数值比较”等有自己的比较逻辑。

| 条件类型 | 常见填写方法 |
| --- | --- |
| 始终满足 | 一般直接不添加条件即可 |
| 目标是自身 | 条件目标选“事件目标”，用于“轮到自己”“自己受伤”等 |
| 目标存活 / 目标死亡 | 配合包含死亡单位；否则死亡单位可能在选目标时就被过滤 |
| 目标是敌人 / 目标是友军 | 判断所选条件目标相对规则拥有者的阵营 |
| 配置编号比较 | 比较选中单位的配置编号 |
| 拥有增益或减益 | 引用编号填写状态编号；取反可表达“没有该状态” |
| 属性比较 | 例如拥有者的攻击 > 100 |
| 生命百分比比较 | 例如拥有者当前生命比例 < 50，表示低于 50% |
| 事件数值比较 | 例如伤害结果数值 > 0；需选择可解析的条件目标 |
| 计数器比较 | 使用全局战斗计数器编号 |
| 回合数比较 | 例如当前回合 >= 3 |
| 目标数量比较 | 比较筛选后目标数量 |
| 计数器与当前回合比较 | 全局计数器与当前回合的关系 |
| 两个动态数值比较 | 比较技能参数、变量、随机值等两个表达式 |

条件取反：把该条条件的判断结果反过来，不会把整组条件改成“或者”。

| 目标类型 | 实际含义 | 易错点 |
| --- | --- | --- |
| 规则拥有者 | 携带该规则的单位 | 被动技能通常用它操作自己 |
| 事件攻击者 | 事件的来源单位 | 治疗、状态事件中未必是传统意义的攻击者 |
| 事件目标 | 当前事件指向的目标单位 | 被动常用；事件没有目标时可能选不到 |
| 技能选中目标 | 本次技能释放命令选出的目标集合 | 当前实现只从“技能释放”事件读取；不要在伤害完成被动里照搬 |
| 全部友军 | 与拥有者同阵营的有效单位 | 包含自身；不要当成“除自己外的友军” |
| 全部敌人 | 与拥有者敌对阵营的有效单位 | 用数量上限时会限制结果 |
| 随机敌人 | 从候选敌人中选一个 | 使用确定性随机源 |
| 生命最低敌人 | 从敌人中选当前生命最低者 | 不是生命最低友军 |
| 攻击最高敌人 | 从敌人中选攻击最高者 | 不是己方最高攻击者 |
| 前排敌人 | 按当前逻辑站位规则挑选前排 | 与模型在屏幕上的位置不是同一个概念 |

需要“治疗生命最低友军”时，在**技能定义 → 目标模式**选择相应友军模式，操作目标用“技能选中目标”。不要选择逻辑下拉框中的“生命最低敌人”。

### 4.3 数值表达式的读法

~~~text
数值来源
  × 固定倍率，或动态倍率
  + 最终偏移
  → 应用最小值
  → 应用最大值
  = 此操作提交的数值
~~~

数值来源分为：

- 固定值：直接填写一个整数。
- 拥有者属性 / 事件攻击者属性 / 当前目标属性：根据上下文读取对应单位。
- 当前生命 / 最大生命 / 已损失生命 / 生命百分比：读取当前目标的数据；生命百分比使用实际百分数（满血为 100）。
- 状态层数：填写状态编号。
- 事件数值：读取当前事件提供的数值。
- 当前回合：读取战斗回合序号。
- 战斗计数器：填写全局计数器编号。
- 策划参数 / 单次触发临时变量 / 技能实例变量：从已声明数据中选择。
- 确定性随机百分比（0%～99.99%）：用于概率比较等需求。

对多个目标造成伤害时，操作会分别建立目标上下文计算数值。若先把“当前目标属性”存进临时变量再群攻，可能只是把当前事件主目标的数据重复用于所有人。按每个目标单独计算时，直接在造成伤害操作中使用对应目标属性更清楚。

### 4.4 逻辑操作速查

| 操作 | 需要关注的字段 | 作用 |
| --- | --- | --- |
| 造成伤害 | 目标、数值、伤害选项 | 进入真正的伤害结算 |
| 恢复生命 | 目标、数值 | 治疗存活单位，受最大生命限制 |
| 添加增益或减益 | 目标、固定或动态状态编号 | 添加已有状态定义 |
| 移除增益或减益 | 目标、固定或动态状态编号 | 移除指定状态，不等于“驱散所有减益” |
| 修改属性 | 目标、修改属性、数值 | 对属性进行数值调整 |
| 修改资源 | 目标、资源属性、数值 | 修改能量等属性 |
| 直接击杀 | 目标 | 逻辑死亡，不是只隐藏模型 |
| 复活 | 死亡目标、数值 | 目标选择应包含死亡单位 |
| 修改逻辑站位 | 目标、数值 | 修改权威逻辑站位，不是演示移动 |
| 累加计数器 | 引用编号、数值 | 修改全局战斗计数器 |
| 设置变量 | 引用编号、数值 | 这里对应全局战斗计数器的设置操作 |
| 结束当前行动 | 通常无额外数值 | 结束当前行动单位的行动；不要随意添加 |
| 设置 / 累加单次触发变量 | 已声明临时变量、数值 | 同条规则内保存中间结果 |
| 设置 / 累加技能实例变量 | 已声明技能变量、数值 | 保存该技能实例的战斗状态 |

### 5.1 表现制作完整流程图

### 5.2 填写基础信息

| 字段 | 本例填写 |
| --- | --- |
| 表现标识 | skill_101012 |
| 逻辑数据源 | skill_logic_101012.asset |
| 每秒帧数 | 30 |
| 自动计算总帧数 | 开启 |
| 总帧数 | 随最晚结束的操作自动计算 |
| 说明 | 关羽突进攻击；第 12 帧受击，第 18 帧返回，第 30 帧结束 |

逻辑数据源应与技能定义里选择的技能逻辑保持一致。即使两个逻辑资产碰巧都有 damage_result，也不要因此混用。

### 5.3 时间轴的五条规则

1. **开始帧是从整个技能开始计算的绝对帧。**第二条轨道的开始帧 0，仍然是技能开始，不是第一条轨道结束。
2. **结束帧 = 开始帧 + 持续帧数。**结束帧由工具计算。
3. **修改开始帧只移动操作，不改变持续时长。**
4. **新加操作会接在该轨道已有操作的最晚结束帧后。**如果要与别的操作同时发生，要手动改开始帧。
5. **列表顺序方便整理；实际启动时间看开始帧。**拖到列表第一行，不会自动把开始帧改为 0。

| 帧数（30 帧/秒） | 对应时间 |
| ---: | ---: |
| 0 | 0 秒 |
| 3 | 0.1 秒 |
| 6 | 0.2 秒 |
| 12 | 0.4 秒 |
| 15 | 0.5 秒 |
| 30 | 1 秒 |
| 60 | 2 秒 |

修改帧率会改变同样帧数对应的实际秒数；不会替你自动重排所有操作。

### 5.4 顺序轨、并行轨、并行组

~~~mermaid
flowchart TD
    A["两个表现操作需要同时发生吗？"] --> B{"它们在同一条轨道？"}
    B -- 否 --> C["分别填写绝对开始帧；不同轨道可以同时播放"]
    B -- 是 --> D{"时间区间有重叠？"}
    D -- 否 --> E["使用顺序轨即可"]
    D -- 是 --> F["轨内方式改为并行，或拆到不同轨道"]
    F --> G["检查是否同时控制同一武将的同一动作、位置或镜头"]
    G --> H{"会互相覆盖？"}
    H -- 是 --> I["错开时间，或拆分控制职责"]
    H -- 否 --> J["检查配置并预览"]
    C --> J
    E --> J
    I --> J
~~~

- 顺序轨：同轨时间区间不能重叠。例如 0～6 后接 6～18 可以，0～6 后接 5～18 不可以。
- 并行轨：允许同轨操作时间重叠。
- 并行组：用于整理轨道。当前播放器按绝对帧执行所有片段，**不同组名不会自动形成前后两段**。
- 逻辑里的“并行”与表现里的“并行”含义不同。逻辑仍按确定性规则和操作顺序结算，不是多线程，也不是同时播放动画。
- 不建议新手同时用两个“播放动作”控制同一武将。需要移动时播攻击，可以安排为位移轨＋动作轨，并核对它们是否争抢同一状态。

### 5.5 可照填的 30 帧最小时间轴

先只创建两条轨道，均为“顺序”。两条轨道可使用同一个并行组名“技能演出”。

**轨道一：施法者动作与位移**

| 操作类型 | 执行对象 | 开始帧 | 持续帧数 | 结束帧 | 资源或其他参数 |
| --- | --- | ---: | ---: | ---: | --- |
| 角色/移动到逻辑目标 | 施法者 | 0 | 6 | 6 | 移动动作可空；偏移可先用 (-0.8, 0, 0)，按模型实际距离调整 |
| 角色/播放动作 | 施法者 | 6 | 12 | 18 | 动作名称 attack_1；必须确认模型存在该动作；循环关闭 |
| 角色/返回原站位 | 施法者 | 18 | 12 | 30 | 返回动作可先留空 |

**轨道二：目标受击与死亡**

| 操作类型 | 执行对象 | 开始帧 | 持续帧数 | 结束帧 | 读取逻辑结果 |
| --- | --- | ---: | ---: | ---: | --- |
| 结算/伤害与飘字 | 逻辑主目标 | 12 | 6 | 18 | damage_result |
| 结算/死亡表现 | 逻辑主目标 | 18 | 12 | 30 | damage_result |

时间示意：

~~~text
帧：       0        6        12        18                 30
施法者：   [ 突进  ][     攻击动作     ][      返回        ]
主目标：                      [ 受击  ][死亡表现：已死亡时]
~~~

本例总时长自动为 30 帧。预览里的死亡检查提示不代表已经进行真实死亡判定；实战中只有逻辑伤害结果已判定死亡才播放死亡表现。

移动偏移是表现坐标。换左右阵营、模型缩放或挂点后要重新看画面，示例 (-0.8, 0, 0) 不是所有武将都通用的站位距离。

### 5.6 再补特效和声音

最小版本通过后，加一条“特效音效”轨，选择“并行”：

| 操作类型 | 执行对象 | 开始帧 | 持续帧数 | 参数 |
| --- | --- | ---: | ---: | --- |
| 特效/挂点特效 | 逻辑主目标 | 12 | 6 | 填真实命中特效资源标识，挂点可留空使用根节点 |
| 音频/播放音效 | 施法者 | 12 | 0 | 填真实音效资源标识，循环关闭 |

音效的 0 帧表示在该帧触发，不表示音频文件本身必须没有长度。带循环或显隐状态的操作，要规划好何时停止或恢复。

没有资源时先不添加对应操作，避免把“待补资源”文字当成资源标识通过流程。

### 5.7 操作参数怎么读

| 字段 | 填写方式 |
| --- | --- |
| 操作类型 | 从分类下拉选择；更改类型会重置该操作的一部分参数，改完重新核对 |
| 操作备注 | 中文备注，用于区分同类片段；不会自动变成动画名 |
| 执行对象 | 施法者或逻辑主目标，不等于固定攻击阵营或防守阵营 |
| 读取逻辑结果 | 选择逻辑资产声明的输出名称；普通动作、移动通常不需要 |
| 动作名称 | 模型内真实存在的动画名，不能随意翻译 |
| 资源标识 | 项目资源加载系统认可的标识，注意大小写与路径规则 |
| 第二资源标识 | 随操作变化：可能是第二挂点、受击特效或特效动画名 |
| 模型挂点 | 模型中存在的节点名称；留空通常使用根节点 |
| 位置偏移 / 终点偏移 | 相对目标或挂点的表现偏移 |
| 演示目标站位 | 仅用于编辑器演示，1～18；实战按逻辑主目标执行 |
| 目标锚点 | 镜头或空间操作参考谁的位置 |
| 强度 | 随操作变化，可能是震动幅度、音量、镜头大小或播放速度 |
| 循环 / 开启 | 循环资源与状态开关，注意结束时的恢复安排 |

### 5.8 哪些操作不能写 0 帧

当前检查要求以下操作持续帧数大于 0：

- 移动到逻辑目标、返回原站位、交换位置。
- 伤害与飘字、颜色闪烁、人物抖动。
- 镜头聚焦、镜头震屏。
- 弹道特效、表现速度。

其他操作是否填 0，要根据触发还是持续播放的需要决定。镜头聚焦的大小、表现速度的倍率还必须大于 0。

### 5.9 时间轴上怎么定位问题

- 点时间轴色块：选中对应轨道和操作。
- 点刻度或拖动“预览帧”：定位到指定帧。
- 选中操作后点“从该操作开始预览”：定位该操作起点。
- 播放到有问题的位置点“暂停”，检查前后几帧。
- 点“停止”：回到第 0 帧，并结束当前演示。
- 修改资源、参数或轨道后，重新检查配置并播放。

一个片段显示“未找到绑定（保留原值）”时，原标识不会再被工具悄悄清空。应修复逻辑数据源或输出定义；只有明确不需要绑定时才选择“不读取逻辑结果”。

## 8. 在基础技能上增加需求

### 8.1 例二：释放时 30% 概率添加状态

**本例明确含义：释放技能时进行一次 30% 判定，通过后给选中目标添加状态。它不等于“伤害命中后才有 30% 概率”。**

准备：战斗定义中必须已有要使用的状态，例如编号 2001；状态的持续、叠层、属性效果由该状态定义负责。

在“参数与变量”增加：

| 程序标识 | 数据编号 | 种类 | 值类型 | 默认值 |
| --- | ---: | --- | --- | ---: |
| trigger_chance | 1002 | 策划参数（只读） | 百分比（%） | 30 |
| buff_id | 1101 | 策划参数（只读） | 配置标识符 | 2001 |

新增一条规则：

| 字段 | 填写值 |
| --- | --- |
| 规则名称 | 释放时概率附加状态 |
| 规则编号 | 10101202 |
| 触发事件 | 技能释放 |
| 执行阶段 | 主阶段 |
| 优先级 | 10 |
| 拥有者必须存活 | 开启 |

条件填写：

| 字段 | 填写值 |
| --- | --- |
| 条件类型 | 两个动态数值比较 |
| 比较方式 | 小于 |
| 左侧数值来源 | 确定性随机百分比（0%～99.99%） |
| 左侧倍率（%） | 100 |
| 右侧数值来源 | 策划参数 |
| 右侧选择参数或变量 | trigger_chance / 1002 |
| 右侧倍率（%） | 100 |
| 两侧最终偏移 | 0 |
| 条件取反 | 关闭 |

操作填写：

| 字段 | 填写值 |
| --- | --- |
| 操作类型 | 添加增益或减益 |
| 操作目标 | 技能选中目标 |
| 数量上限 | 0 |
| 动态引用编号 | 开启 |
| 引用编号数值 → 数值来源 | 策划参数 |
| 引用编号数值 → 选择参数或变量 | buff_id / 1101 |
| 引用编号数值 → 倍率（%） | 100 |
| 引用编号数值 → 最终偏移 | 0 |

~~~mermaid
flowchart TD
    A["该单位释放本技能"] --> B["读取 trigger_chance"]
    B --> C["取得一次 0%～99.99% 的确定性随机百分比"]
    C --> D{"随机数小于 30？"}
    D -- 否 --> E["本条状态规则不执行"]
    D -- 是 --> F["读取 buff_id"]
    F --> G["给技能选中目标添加该状态"]
    G --> H["状态定义负责持续、叠层和属性效果"]
~~~

注意：

- 当前规则只判定一次概率，随后对选中的目标执行操作；这不等于对每个目标单独掷一次概率。
- “添加状态”的操作参数不是伤害倍率，也不是状态层数；持续与叠层应检查状态定义。
- 想改成“伤害成功后附加”，需要使用伤害完成事件并过滤来源与有效伤害；想再限定为某一个技能，还要确认当前事件是否提供足够的来源技能信息。
- 不要给时间轴加一个“附加成功”的固定文字就当成概率结果展示。当前状态飘字不会仅凭输出名称自动按添加成功事件过滤。

验收顺序：

1. trigger_chance 临时设为 100，确认状态确实能添加。
2. 改成 0，确认不会添加。
3. 恢复 30，进行多次不同释放或不同测试种子的统计。
4. 使用同一随机种子、相同命令重复一局，结果应可重现；重复相同的一次释放并不是新的独立随机样本。
5. 提交前确认恢复了正式概率。

### 8.2 例三：自己的行动开始时，生命低于 50% 就回血 100

新建独立逻辑资产。新建会带伤害模板，因此先删除不需要的伤害操作，并确保最终只保留本例需要的规则和操作。

技能定义的“主动技能”关闭，使其作为被动规则注册。单位除了被动，还应保留可用的主动技能。

| 规则字段 | 填写值 |
| --- | --- |
| 规则名称 | 自己行动开始时低血量回血 |
| 规则编号 | 另行分配，例如 10101301 |
| 触发事件 | 行动开始 |
| 执行阶段 | 主阶段 |
| 优先级 | 0 |
| 拥有者必须存活 | 开启 |

配置两条条件，全部满足：

| 条件 | 条件类型 | 条件目标 | 比较方式 | 比较值 |
| --- | --- | --- | --- | ---: |
| 1 | 目标是自身 | 事件目标 | 不需要 | 不需要 |
| 2 | 生命百分比比较 | 规则拥有者 | 小于 | 50 |

配置一个操作：

| 字段 | 填写值 |
| --- | --- |
| 操作类型 | 恢复生命 |
| 操作目标 | 规则拥有者 |
| 数值来源 | 固定值 |
| 固定值 | 100 |
| 倍率（%） | 100 |
| 最终偏移 | 0 |

~~~mermaid
flowchart TD
    A["某个单位行动开始"] --> B{"事件目标是本规则拥有者？"}
    B -- 否 --> X["不回血"]
    B -- 是 --> C{"拥有者当前生命比例小于 50%？"}
    C -- 否 --> X
    C -- 是 --> D["给拥有者恢复 100 点生命"]
    D --> E["实际治疗量受最大生命限制"]
~~~

为什么必须有第一条条件：行动开始事件会被注册了该事件的被动规则观察。没有“事件目标是自身”，别人的行动开始也可能触发你的回血。

被动逻辑产生治疗事件，不意味着技能定义中绑定的整段时间轴会自动在这次被动上播放。当前整段技能表现主要由主动技能释放事件启动；被动专属整段演出需要项目另外接入。

### 8.3 例四：把单体伤害改为群体伤害

1. 技能定义“目标模式”改为“全部敌人”。
2. 造成伤害操作的目标保持“技能选中目标”。
3. 数量上限保持 0。
4. 检查所有条件是否误要求“全部敌人都符合某个属性条件”。
5. 进入多敌人的战斗，确认每个目标都正确扣血。

当前表现播放器主要围绕一个主目标和一条匹配伤害结果工作。群体逻辑可以逐个结算，但“每个敌人分别出完整时间轴”“每段伤害分别绑定不同飘字”不能只复制几段主目标操作就保证正确，需要先确认项目扩展能力。

## 9. 表现操作全表：按需求找类型

表中的“资源必填”表示当前检查要求标识非空，不代表检查时已经验证该资源真实可加载。

## 10. 排错流程图与对照表

~~~mermaid
flowchart TD

    B -- 是 --> C["按窗口提示检查编号、引用、作用域、帧区间和资源标识"]
    B -- 否 --> D{"编辑器连模型都没有？"}

    D -- 否 --> F{"只是动作、位移或节奏不对？"}
    F -- 是 --> G["检查真实动作名、执行对象、绝对帧和重叠控制"]
    F -- 否 --> H{"Battle 中没有技能按钮或不能释放？"}
    H -- 是 --> I["检查技能定义、注册列表、单位技能编号、主动开关和消耗"]
    H -- 否 --> J{"实际扣血、回血或状态不对？"}
    J -- 是 --> K["检查规则触发、条件目标、倍率、属性、护盾与队列结果"]
    J -- 否 --> L["检查真实资源加载、主目标限制和场景扩展"]
    C --> M["修正后复测"]
    E --> M
    G --> M
    I --> M
    K --> M
    L --> M
~~~

| 现象 | 优先检查 |
| --- | --- |
| 一直是一号位赵云在播放 | 预览施法者是否仍是“自动”；只点站位格子不会切换角色 |
| 切了预览武将，Battle 里没变化 | 预览阵容与 Units / View Prefab 是两套配置 |
| 模型出现，但不播放攻击 | 动作名称是否真实存在、执行对象是否正确、是否被另一动作覆盖 |
| 编译通过但特效、声音没有 | 标识是否能被资源系统加载；编辑器是否只显示了预览提示 |
| 第二条轨道从头播放了 | 开始帧为绝对帧；需要延后就填写更大的开始帧 |
| 改了开始帧，结束位置也变化 | 结束帧 = 开始帧 + 持续帧数，持续时长被保留 |
| 刚添加的特效出现在技能末尾 | 新增操作默认追加在本轨最晚结束帧；手动改为命中帧 |
| 顺序轨道提示重叠 | 调整区间，或选择并行 / 拆轨 |
| 手动总帧数超范围 | 总帧数必须覆盖所有操作结束帧，或开启自动计算 |
| 读取逻辑结果里找不到名称 | 逻辑数据源错误、输出未声明、名称被改 |
| 出现“保留原值”的缺失绑定 | 原引用未被清空；修复输出或主动清除绑定 |
| 参数下拉没有想选的变量 | 数据种类或作用域不符合当前操作 |
| 伤害变成了 100 倍 | 误把 135% 写成旧格式 13500，应改填 135 |
| 伤害只剩很小一点 | 想配置 135% 却填写了 1.35；现在应直接填写 135 |
| 同一技能打了两次伤害 | 新建模板已有伤害操作，又重复添加 |
| 变量在下一条规则不见了 | 使用了单次触发变量；跨规则状态用技能实例变量 |
| 别人行动时自己也回血 | 行动开始被动缺少“事件目标是自身”的条件 |
| 被动里选“技能选中目标”没有效果 | 此选择器当前依赖技能释放事件，被动应检查事件目标等 |
| 0% 状态概率仍看到“添加成功”飘字 | 固定时间轴文字没有自动按状态结果过滤 |
| 30% 概率连续多次结果一样 | 同种子同命令可重现；不是每次重进都生成新随机结果 |
| 死亡触发规则不执行 | 拥有者必须存活限制、死亡目标过滤、事件条件 |
| 治疗没效果 | 目标已死亡、已满血、目标选成敌人或数值不大于 0 |
| 技能按钮不出现 | 主动开关、Generated Skill Assets、Units/Skill Ids、当前行动单位 |
| 保存逻辑成功，进 Battle 却报编号重复 | 单资产检查不能代替战斗整体编号检查 |
| 换背景 / 模型 / 格子操作没反应 | 对应项目扩展与场景绑定是否存在 |
| 多目标只看到一个完整演出 | 当前时间轴主要围绕主目标；需核对多目标表现扩展 |
| 旧技能资产闭环自检失败 | 该自检依赖特定参考资产；先看缺失引用或固定样例不匹配，不能直接认定新技能错误 |

## 11. 当前规则的能力边界

这些是本次核对代码得到的实际边界。配置超出范围的需求时，先把需求交给程序确认，避免不断调整界面数值但无法实现。

| 需求 | 当前情况 |
| --- | --- |
| 主动单体伤害、治疗、已有状态添加或移除 | 可用现有逻辑组合，仍需实战验收 |
| 参数、动态倍率、概率、临时变量、技能实例变量 | 已有对应能力 |
| 根据事件做自身条件判断与计数 | 可用，但必须正确限定事件来源 / 目标 |
| 多个逻辑操作“并行计算” | 仍按确定性顺序处理，分组不等于并行线程 |
| 伤害结算前直接改最终伤害 | 没有完整可配置的前置伤害修改管线 |
| 在表现编辑器召唤一个新的逻辑单位 | 不支持；入场表现仅展示已有单位 |
| 按标签批量驱散、免疫、精确改状态层数 | 不能假定已有对应通用操作 |
| 保存任意目标集合后跨规则复用 | 当前变量是数值，不是目标集合容器 |
| 给输出标识随便起名即可自动读取任意事件数据 | 不支持通用自动路由；目前以声明与引用校验为主 |
| 状态 / 治疗 / 死亡事件自动启动任意绑定时间轴 | 不保证；主动技能时间轴主要从技能释放启动 |
| 多段伤害与多个敌人的表现逐段精确匹配 | 当前主目标与单条伤害结果机制有限，需要扩展 |
| 表现预览能代替实战资源加载验证 | 不能，部分操作只有提示或示意 |
| 切换背景、替换模型、刷新格子 | 需要对应场景或项目扩展绑定 |
