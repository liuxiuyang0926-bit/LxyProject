0. 先分清“配置结果”和“播放画面”

技能逻辑资产回答：什么时候触发、满足什么条件、影响谁、造成多少伤害或治疗、添加什么状态。

技能表现资产回答：第几帧播放动作、第几帧移动、在哪里出特效、什么时候显示受击与死亡画面。

技能定义资产把逻辑、表现、技能编号、消耗和选目标方式组合起来。只有创建逻辑和表现文件，技能还没有进入战斗。

战斗定义资产配置参加战斗的单位、属性、携带技能和可用的技能定义。

18 位阵容预览资产配置编辑器演示用的模型和站位。换预览武将，不会给实战单位换技能、攻击力或模型。

想改什么去哪里改一个例子
伤害从 135% 改为 150%技能逻辑 → 参数与变量damage_rate：135 → 150
伤害数字出现得晚一点技能表现 → 伤害与飘字开始帧：12 → 15

预览时用关羽，不用赵云预览角色 → 预览施法者选择 2 号位关羽
实战关羽携带这个技能战斗定义 → Units → Skill Ids添加该技能编号
模型本身没有指定动作模型动画资源核对真实动作名，不能靠改备注解决

请先记住四条规则：

  1. 表现编辑器中的“播放”不进行真正的战斗数值计算。
  2. 在表现时间轴上多放一个“伤害与飘字”，不会增加一次逻辑伤害。
  3. 把“死亡表现”放到某一帧，不会把活着的单位杀死。
  4. “检查配置”通过，说明当前结构和引用检查通过；资源能否加载、被动是否正确触发，还要进入战斗验证。

3.2 新建时已经有什么

新建逻辑资产默认带有主动伤害示例，通常已经包含：

  • 一个伤害结算轨道。
  • 一条“技能释放”规则。
  • damage_rate 参数。
  • temp_value 单次触发变量。
  • cast_count 技能实例变量。
  • 依次“计算伤害 → 造成伤害 → 累计释放次数”的三个操作。
  • damage_result 输出声明。

先检查并修改默认内容，不要在已有伤害操作后又新增一份相同伤害。

顶部“数据模板”只补充数据定义，不会替你写出完整的新规则。已有同名定义不会被覆盖；推荐编号被占用时，模板会选择后续可用编号。引用时以实际生成的数据编号为准，优先使用下拉框。

3.5 所有百分比都填写实际百分数

统一规则：135% 填 135，30% 填 30，12.5% 填 12.5。无需手动放大数值。

所在位置与字段100%135%30%
逻辑编辑器、普通 Inspector 的“倍率（%）”10013530
数据定义“默认值”，值类型为“百分比（%）”10013530
动态倍率读取的百分比参数或变量10013530
动态倍率的“固定倍率（%）”10013530
生命百分比条件的“比较值（%）”100不适用于正常生命比例30

百分比支持两位小数，例如 12.55%。概率通常填写 0～100；伤害倍率和暴击伤害可以超过 100。整数、计数和配置编号仍填写整数。

生命比例、随机百分比、暴击率等百分比来源会自动识别单位：例如“生命比例 < 固定值 50”表示低于 50%，“随机百分比 < 固定值 30”表示 30% 概率。对百分比变量执行“设置/累加”时，固定值和偏移也使用实际百分数，例如累加 5 表示增加 5 个百分点。

动态倍率应引用“百分比（%）”类型的参数或变量。独立的固定百分比表达式可以开启“固定值使用百分比”；通常按比较对象或目标变量自动识别即可。

更新工具后，旧战斗配置会按版本标记自动迁移一次，保留原来的数值效果，无需手动执行迁移命令。编译后的定点数内部表示由工具处理，策划只编辑实际百分数。

例：动态倍率已经读取 damage_rate = 135 时，不要再额外乘一遍 135%。

三个操作按以下顺序排列：

1. temp_value = 自身攻击 × damage_rate
2. 用 temp_value 对选中目标造成伤害
3. cast_count 加 1

“伤害在列表前面，计算变量在后面”会读到错误的中间值。

3.11 保存与检查

点击 “检查配置”。通过后工具会保存；也可以单独点“保存”。

失败时先读窗口里的具体错误：

  • 编号不存在：到“参数与变量”检查定义，再从下拉框重新选择。
  • 参数 / 变量种类或作用域不匹配：例如“设置技能实例变量”不能引用单次触发变量。
  • 规则编号重复：修改“规则高级设置”里的编号；资产间是否重复还要检查整体战斗编译。
  • 规则没有操作：至少保留一个有效操作。
  • 布尔默认值错误：只能填写 0 或 1。
  • 最小值大于最大值：调整上下限。
  • 输出标识为空或重复：整理输出列表。

4.3 数值表达式的读法

数值来源
  × 固定倍率，或动态倍率
  + 最终偏移
  → 应用最小值
  → 应用最大值
  = 此操作提交的数值

数值来源分为：

  • 固定值：直接填写一个整数。
  • 拥有者属性 / 事件攻击者属性 / 当前目标属性：根据上下文读取对应单位。
  • 当前生命 / 最大生命 / 已损失生命 / 生命百分比：读取当前目标的数据；生命百分比使用实际百分数（满血为 100）。
  • 状态层数：填写状态编号。
  • 事件数值：读取当前事件提供的数值。
  • 当前回合：读取战斗回合序号。
  • 战斗计数器：填写全局计数器编号。
  • 策划参数 / 单次触发临时变量 / 技能实例变量：从已声明数据中选择。
  • 确定性随机百分比（0%～99.99%）：用于概率比较等需求。

对多个目标造成伤害时，操作会分别建立目标上下文计算数值。若先把“当前目标属性”存进临时变量再群攻，可能只是把当前事件主目标的数据重复用于所有人。按每个目标单独计算时，直接在造成伤害操作中使用对应目标属性更清楚。

5.8 哪些操作不能写 0 帧

当前检查要求以下操作持续帧数大于 0：

  • 移动到逻辑目标、返回原站位、交换位置。
  • 伤害与飘字、颜色闪烁、人物抖动。
  • 镜头聚焦、镜头震屏。
  • 弹道特效、表现速度。

其他操作是否填 0，要根据触发还是持续播放的需要决定。镜头聚焦的大小、表现速度的倍率还必须大于 0。

  • 选中操作后点“从该操作开始预览”：定位该操作起点。
  • 播放到有问题的位置点“暂停”，检查前后几帧。
  • 点“停止”：回到第 0 帧，并结束当前演示。
  • 修改资源、参数或轨道后，重新检查配置并播放。

11. 当前规则的能力边界

这些是本次核对代码得到的实际边界。配置超出范围的需求时，先把需求交给程序确认，避免不断调整界面数值但无法实现。

需求当前情况
主动单体伤害、治疗、已有状态添加或移除可用现有逻辑组合，仍需实战验收
参数、动态倍率、概率、临时变量、技能实例变量已有对应能力
根据事件做自身条件判断与计数可用，但必须正确限定事件来源 / 目标

表现预览能代替实战资源加载验证不能，部分操作只有提示或示意
切换背景、替换模型、刷新格子需要对应场景或项目扩展绑定
