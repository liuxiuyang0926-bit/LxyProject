# BattleLogic 参考工程分析与迁移边界

本文记录 `Assets/Temp/BattleLogic` 的静态分析结论，以及当前回合制运行时对旧 Lua 能力的承接方式。参考目录只用于理解业务语义，不参与正式 Battle 构建。

## 1. 规模与主要模式

- 目录约 7677 个文件，其中约 3820 个 Lua 脚本。
- 技能脚本约 1491 个：主动技能约 568、状态被动约 519、行动被动约 246。
- Buff 脚本约 2043 个，AI 脚本约 199 个。
- 高频能力包括添加 Buff、目标列表、伤害、按位置找单位、自动选敌、技能缓存、移除 Buff、概率判定、召唤、治疗和格子变化。
- 高频触发包括主动释放、入场、战斗开始、受击、死亡、行动后、回合开始、生命变化和回合结束。

旧工程中技能等级数组、`getSkillCache/setSkillCache`、临时局部变量和 `RandomManager` 是复杂技能的四类基础数据来源。因此本轮优先建立参数、变量作用域、动态比较、动态倍率和确定性随机，而不是逐文件翻译 Lua。

## 2. 当前对应关系

| 旧 Lua 语义 | 当前实现 |
| --- | --- |
| 技能等级数组、策划系数 | `BattleLogicDataKind.Parameter` |
| 函数内局部中间值 | `InvocationVariable`，每条规则触发后清空 |
| `getSkillCache/setSkillCache` | `SkillVariable`，按技能运行时实例隔离 |
| `checkRateSuccess` | `RandomBasisPoint < trigger_chance` 动态条件 |
| 数值系数参与伤害/治疗 | 数值表达式的动态倍率 |
| 两个运行时值比较 | `LogicValueCompare` |
| 固定或参数化 Buff ID | Action 固定引用 ID / 动态引用 ID |
| Lua Parallel 分支 | 轨道并行语义 + Phase/Priority/Owner/RuleId 确定性结算 |
| 伤害、治疗、Buff、死亡、复活、站位 | 既有 Command/Action/Event/Service 闭环 |

技能实例变量使用 `(RuntimeSkillInstanceId, DataKey)` 作为地址，以有序容器存储并写入战斗状态哈希。相同配置、Seed 和指令必须得到相同事件序列与哈希。

## 3. 没有照搬的旧结构

以下结构被明确排除：

- 全局 `BattleLogic` 服务定位器。
- 逻辑层直接控制特效、镜头、声音或协程。
- `pairs` 等无稳定遍历次序的数据参与权威结算。
- 运行时通过字符串动态查找任意方法。
- Action 递归跳过、遍历中重排行动队列、未统一释放监听器等隐式生命周期。

当前结构继续保持 Logic → Presentation 单向输出，权威逻辑不依赖 Unity `Time`、`Random`、物理查询或 GameObject 状态。

## 4. 已知待扩展能力

本轮没有假装覆盖全部旧脚本。下列能力需要独立的数据契约与专项验证后再开放给策划：

1. 伤害前可修改管线：`BeforeDamage` 已有事件枚举，但尚未提供可组合的伤害修正上下文。
2. 召唤工厂：运行时已有 `SummonService`，仍需由 Entity/Monster 配置稳定构造属性、技能和唯一 UnitId。
3. 行动条推进/拉退：需要避免结算中重排导致当前行动者漂移，并明确同值排序规则。
4. 驱散、Buff 层数精确修改、标签筛选和免疫体系。
5. 目标集合变量、按站位集合运算、空位选择和多段目标重选。
6. 每个目标独立的表现数据负载，以及多段伤害与表现帧的关联 ID。
7. AI 条件树、波次、掉落、成就记录等战斗外服务适配器。

新增能力应遵循同一准入条件：有稳定序列化格式、编辑器校验、确定性排序、状态哈希覆盖、最小闭环自检，并且不让表现反向修改权威逻辑。

## 5. 推荐迁移流程

1. 从一个旧技能提取触发事件、目标、参数、临时值、整场缓存和输出事件。
2. 在逻辑编辑器先建立数据定义，再按规则拆分条件和 Action。
3. 复杂公式用临时变量分步计算；跨触发状态只放技能实例变量。
4. 为随机条件显式配置万分比参数，不使用 Unity 随机数。
5. 保存并运行“校验编译”和“逻辑临时数据自检”。
6. 生成 C# 进行代码评审，再把技能定义加入 `TurnBasedBattleDefinition`。
7. 使用固定 Seed 与 Command 录制黄金事件轨迹，和旧工程结果对照。

若某个 Lua 技能需要“已知待扩展能力”，先扩展通用运行时能力，不应把项目特例硬编码到通用 RuleEngine。
